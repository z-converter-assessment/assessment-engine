## 끝난 일 (다시 시작하지 말 것)

34단계 현대화 계획을 전부 반영했고 1.3.1 ~ 1.3.3 세 릴리즈로 나갔다. 계획 문서는 세션 스크래치패드에만
있었고 지금은 없다 — 결과는 코드와 영구 문서가 갖고 있으므로 복원할 필요 없다.

의도적으로 하지 않은 것 하나만 기록에 없으니 적는다. **`_action` 의 목표 키를 자원별 분기로 편 것을 다시
`_TARGET_KEY` dict 로 되돌리지 말 것** — 변수 키 대입(`a[key] = v`)은 pyright 가 검사하지 못해 TypedDict
전환의 이득이 그 자리에서만 사라진다. 짧아 보여서 되돌리기 쉬운 형태다.

의식적으로 유예한 설계 하나는 `docs/explanation/tradeoffs.md` T24 에 있다 (`disk_baseline` 을 보고서
경로에만 주입). 통일하면 화면 분류가 실제로 바뀌므로 계약 개정 절차가 필요하다.

## 재현해야 할 검증 수단

세션 스크래치패드에 있던 것이라 지금은 없다. 다시 필요하면 이 방식으로 만든다.

- **브라우저 오라클** — `tests/http/conftest.py` 의 대역 배선을 그대로 써서 uvicorn 을 띄우고
  (`app.dependency_overrides` + `lifespan="off"`), playwright 로 16페이지를 돌며 콘솔 에러·canvas 렌더 수·
  전역 표면을 JSON 으로 덤프해 전후 대조. 클라 JS 를 건드릴 때 유일한 런타임 오라클이다.
- **SQL 대조** — repo 메서드에 recorder 세션을 주입해 렌더된 SQL 문자열과 params 를 전 Literal 조합에
  대해 덤프. `metric_trend` 같은 dispatch 를 재배치할 때 썼다.

둘 다 일회성이라 저장소에 두지 않았다. 상시 필요해지면 `tests/` 로 승격하는 것이 맞다.

## 알아 둘 함정

- **HTTP 스냅샷은 화면 구조만 지킨다.** 엔진 버전·`?v=` 토큰·발행 시각은 정규화로 지운다. 버전이 화면에
  찍히는지 자체는 `test_engine_version_is_rendered` 가 따로 본다.

  픽셀 대조할 때는 "before-after 차이"를 "after-after 차이"와 비교해야 판단이 선다.

  검증은 `alembic-check.yml` 잡이나 통합 테스트(testcontainers)가 맡는다.
