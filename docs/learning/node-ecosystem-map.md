# Node 생태계 대응표 — 파이썬 기준

학습 자료. 기준 시점 2026-08-03, 커밋 `fa89b1f`. 갱신 의무 없음.

파이썬 도구 체인을 아는 상태에서 Node 쪽을 읽을 때 필요한 최소 어휘를 세운다. 1절부터 3절이 L2, 4절이 L3 다.

## 1. 역할이 그대로 대응한다

새 개념이 아니라 같은 역할의 다른 이름이다.

| 역할 | 파이썬 | Node |
|------|--------|------|
| 런타임 | python | node |
| 패키지 매니저 | uv (pip) | pnpm (npm · yarn) |
| 프로젝트 설정 파일 | `pyproject.toml` | `package.json` |
| lockfile | `uv.lock` | `pnpm-lock.yaml` |
| 설치된 패키지가 쌓이는 곳 | `.venv/` | `node_modules/` |
| 명령 실행 | `uv run <명령>` | `pnpm run <이름>` |

패키지 매니저가 여럿인 사정도 같다. npm 이 Node 기본 동봉이고, yarn 이 2016년쯤 대안으로 나왔고, pnpm 이 최근 채택이 늘었다. pnpm 은 전역 저장소에 패키지를 한 벌만 두고 각 프로젝트에는 링크만 걸어 디스크와 설치 시간을 줄인다 — pip 대비 uv 와 같은 세대의 개선이다.

버전은 `package.json` 의 `packageManager` 필드로 고정한다. 사람마다 다른 매니저 버전을 써서 lockfile 이 갈리는 것을 막는다.

## 2. 파이썬에 없는 것 — scripts 필드

`package.json` 에는 `pyproject.toml` 에 대응이 없는 칸이 하나 있다. 긴 명령에 짧은 이름을 붙여 두는 자리다.

```json
"scripts": {
  "typecheck": "tsc --noEmit"
}
```

이렇게 두면 `pnpm run typecheck` 로 부른다. 이름은 우리가 짓는 것이고 도구 이름이 아니다. 여러 명령을 `&&` 로 이어 한 이름에 묶을 수도 있어서, 이름만 보고는 안에서 무엇이 도는지 알 수 없다.

그래서 이름이 짧을수록 설명하는 문서가 무엇을 하는지 대신 말해줘야 한다. 이름 하나만 인용하고 넘어가면 읽는 쪽에 아무것도 전달되지 않는다.

## 3. 기성품을 가져오는 경로가 둘이다

외부 라이브러리를 쓰는 방법이 두 가지이고 목적이 다르다.

| 경로 | 어디에 놓이나 | 누가 쓰나 |
|------|--------------|-----------|
| 패키지 매니저로 설치 | `node_modules/` | 개발 머신의 도구 |
| 파일을 직접 커밋 | 저장소 안 정적 자원 디렉토리 | 브라우저 |

브라우저는 `node_modules/` 를 볼 수 없다. 브라우저가 받는 것은 서버가 HTTP 로 내려주는 파일뿐이다. 그래서 화면에서 쓸 라이브러리는 압축본 파일을 받아 저장소에 커밋하고 HTML 의 `<script src="...">` 로 부른다.

번들러를 쓰는 프로젝트는 이 구분이 흐려진다. 번들러가 `node_modules/` 의 코드를 읽어 브라우저용 파일 한 장으로 합쳐 주기 때문이다. 번들러가 없으면 두 경로가 분리된 채로 남는다.

같은 라이브러리가 양쪽에 다 있을 수 있다. 브라우저용 압축본은 커밋해 두고, 타입 검사기가 참조할 사본만 패키지 매니저로 받는 식이다. 이때 두 사본의 버전이 어긋날 수 있다는 점을 의식해야 한다 — 검사는 새 버전 기준으로 통과시키고 브라우저는 옛 버전을 실행하는 상태가 된다.

## 4. 이 저장소에서 Node 가 하는 일

화면을 만들지 않는다. 번들러가 없고 빌드 산출물도 없다.

브라우저에 나가는 것은 셋이다. 서버가 Jinja2 로 만든 HTML, 정적 자원 디렉토리의 `.js` 파일들, 그리고 거기 함께 커밋된 외부 라이브러리 압축본이다. 이 셋 중 어느 것도 Node 를 거치지 않는다.

Node 는 두 가지만 한다.

- 타입 검사 — `tsc` 가 `.js` 파일을 읽어 서버가 선언한 응답 타입과 맞는지 본다
- 타입 생성 — 서버의 API 설명서에서 TS 타입 파일을 만든다 (`docs/reference/web/type-contract.md` 가 정본)

`node_modules/` 는 개발 머신에만 있다. 이미지에도 wheel 에도 들어가지 않고, 배포 VM 은 Node 가 설치돼 있지 않아도 된다.

`package.json` 의 자기 설명이 그 경계를 적어 둔다 — dev/CI 전용이며 빌드·번들·런타임 산출물이 없다.
