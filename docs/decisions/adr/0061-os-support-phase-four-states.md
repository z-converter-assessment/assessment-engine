# ADR 0061 — OS 지원 단계를 경계 3개 기준 4상태로 판정

상태: Accepted (2026-08-04)

Refines: ADR 0031 (OS EOL 운영신호 — endoflife.date 스냅샷 카탈로그)

## Context

ADR 0031 이 EOL 판정을 endoflife.date 스냅샷 카탈로그로 세웠다. 그 결정에서 카탈로그가 싣는 것은 `eol` 하나였고 판정은 경과 여부 이단이었다.

이후 Windows Server 를 다루면서 `support` 를 함께 싣고 상태를 셋(지원 중 / 연장지원 / 종료)으로 늘렸으나 결정 기록을 남기지 않았다. 본 ADR 이 그 구간까지 함께 덮는다.

세 가지가 남아 있었다.

데이터를 버리고 있었다. endoflife.date 는 릴리즈마다 경계 셋을 주는데 카탈로그는 Linux 에서 `eol` 하나만 취했다. `support` 를 주는 product 가 7개, `extendedSupport` 를 주는 product 가 6개인데 전부 버렸다.

용어가 충돌했다. Microsoft 는 무상 보안 패치만 나오는 구간을 Extended Support 라 부르는데 endoflife.date 필드 `extendedSupport` 는 그 이후 유상 구간을 가리킨다. 같은 말이 정반대를 뜻한다. 코드가 전자를 `extended` 라 부르고 있어 카탈로그 필드명과 어긋나 있었다.

판정이 표시에 묶여 있었다. 상태 셋이 곧 화면에 뜨는 셋이라, 표시를 바꾸려면 판정을 바꿔야 했다.

## Decision

경계를 벤더 용어가 아니라 무엇이 끊기는지로 정의한다.

| 경계 | 끊기는 것 |
|------|-----------|
| `support` | 기능 업데이트 |
| `eol` | 무상 보안 패치 |
| `extendedSupport` | 유상 보안 패치 |

이 축은 벤더를 가리지 않는다. Windows Server 2012 R2 의 Mainstream·Extended·ESU 와 RHEL 8 의 Full·Maintenance·ELS 가 실측으로 같은 자리에 온다.

판정 상태는 넷이다. 카탈로그 미매칭은 `None` 으로 두어 판정 불가와 구분한다.

| 상태 | 조건 |
|------|------|
| `full` | support 미도래 (또는 support 미수록 + eol 미도래) |
| `security_only` | support 경과 + eol 미도래 |
| `paid_only` | eol 경과 + extendedSupport 미도래 |
| `ended` | extendedSupport 경과, 또는 eol 경과인데 유상 경로 부재 |

벤더 용어를 상태명에 쓰지 않는다. 위 충돌 때문이고, 이름만 보고 어느 구간인지 알 수 있어야 한다.

카탈로그는 경계 셋을 다 싣는다. 값이 날짜가 아니면 키 자체를 넣지 않아 소비자가 유무로 판단한다 — 없는 경계는 그 구간이 존재하지 않는다는 뜻이다.

판정을 표시보다 잘게 유지한다. 화면마다 4상태를 다르게 접어 쓴다. 서버 목록 필터는 셋으로(패치 종료 / 유지 / 미상), 환경 요약 KPI 는 넷으로 접는다. 표시를 바꿀 때 판정을 건드리지 않아도 되게 하려는 것이 이 분리의 목적이다.

발화 조건은 무상 보안 패치가 끊긴 시점이다 — `paid_only` 와 `ended` 둘 다 발화한다. 유상 계약 여부는 에이전트가 수집할 수 없으므로 계약이 없다는 쪽으로 본다.

## Consequences

Linux 도 경계 셋을 갖는다. ubuntu·rhel 계열은 기능 업데이트 종료와 무상 패치 종료를 구분해 표시하고, 유상 연장 경로가 있는 배포는 그 사실이 드러난다.

발화 집합은 이전과 같다. 카탈로그 전수에서 `extendedSupport` 가 `eol` 보다 이른 항목이 없어, 새 조건이 옛 조건과 같은 호스트 집합을 낸다. 운영자가 받는 경고는 달라지지 않는다.

표시 계층이 판정과 독립적으로 움직인다. 화면을 늘리거나 접는 변경이 판정 코드를 건드리지 않는다.

Windows 커널 build 가 복수 채널에 겹치면 후보 전체를 판정한 뒤 심각도 최소를 택한다 — 불확실할 때 과소지원으로 오판하지 않는 쪽이다.

## Tradeoffs / 한계

유상 계약 여부를 모른다. `paid_only` 호스트가 실제로 패치를 받는지는 고객사 계약에 달렸고 수집할 수 없다. 계약이 없다는 쪽으로 보므로 계약을 맺은 호스트는 과대 경고를 받는다.

카탈로그가 경계를 다 싣지 못한다. fedora·opensuse 는 유상 연장이 없어 무상 종료가 곧 `ended` 이고, debian·sles 는 `support` 가 없어 `security_only` 구간이 없다. 제공처가 주지 않는 경계는 만들지 않는다.

과거 보고서 스냅샷은 옛 어휘를 갖고 있다. 보고서가 발행 시점 정적 스냅샷이라 옛 상태 문자열이 그대로 되살아나므로, 역직렬화에서 새 어휘로 옮긴다.

ADR 0031 의 한계는 그대로다 — 미등록 OS 침묵, 정적 스냅샷의 시차, Windows Server 가정.
