# ADR (Architecture Decision Record)

되돌리기 비싼 결정을 남기는 자리다. 무엇을 정했고 그때 무엇을 알고 있었는지를 적는다. 지금 코드가 어떻게 도는지는
`docs/reference/` 가 갖고, 왜 그 한계를 안고 가는지는 `docs/explanation/tradeoffs.md` 가 갖는다.

## 언제 쓰나

다음 셋 중 하나면 쓴다.

- 대안이 있었고 그중 하나를 골랐다. 고른 이유가 코드에 남지 않는다.
- 되돌리려면 데이터 마이그레이션이나 배포 절차 변경이 필요하다.
- 나중에 누군가 "왜 이렇게 안 했지"라고 물을 것이 예상된다.

반대로, 코드를 읽으면 알 수 있는 것과 언제든 바꿀 수 있는 것은 쓰지 않는다.

## 규약

파일명은 `NNNN-짧은-제목.md` (4자리 zero-padded). 번호는 `0001` 부터 단조 증가하고 재사용하지 않는다.

본문 권장 구성은 Status / Context / Decision / Consequences 다. 형식보다 중요한 것은 Context 에 그때의 제약을
남기는 것이다 — 결정은 제약이 바뀌면 뒤집힌다.

결정이 바뀌면 새 ADR 을 쓰고 이전 ADR 의 Status 에 `Superseded by NNNN` 을 단다. 지난 결정을 지우거나 덮어쓰지
않는다.

기록의 오류는 다르다. 사실과 다른 수치·이름·서술은 그 결정의 근거가 아니라 흠이므로 본문에서 바로 고친다. 판단
기준은 하나다 — 그때의 결정이 달라지면 새 ADR, 그때의 기록이 틀렸으면 본문 수정.

## 라이브 문서와의 관계

`docs/reference/`·`docs/guides/`·`docs/explanation/` 은 ADR 을 인용하지 않는다. 아카이브에 의존하면 현황 문서를
읽는 데 이력을 따라가야 하고, ADR 이 낡으면 현황까지 함께 낡는다. 결정이 코드에 반영됐으면 그 사실은 현황 문서가
자기 말로 적는다.

## 목록

아직 없다. 현재 상태는 코드와 `docs/reference/` 가 갖고, 여기부터는 앞으로의 결정만 쌓인다.
