리더 피드백 항목별 조치 결과와 미처리 근거를 기록한다.

## 1. 서버 세부사항 — 더 구체적인 서버 정보 표시

**목표**: 서버 목록 또는 상세 페이지에서 "이 서버가 무슨 서버인지" 즉시 파악 가능하게.

### 조치 완료
- External IP 유무를 "퍼블릭" / "내부망" 뱃지로 표시 (리스트 + 상세 페이지)

### 미처리
- 마운트 포인트 기반 역할 추론
  - 마운트 포인트 경로(`/data`, `/backup` 등)는 관리자의 네이밍 관례에 의존한다. `/data`가 DB 데이터 디렉토리일 수도 있고, 단순 파일 저장소일 수도 있다. 기술적으로 강제된 규약이 아니므로 이를 바탕으로 서버 역할을 추론하는 것은 신뢰할 수 없는 설계다.


- 실행 중인 서비스·프로세스 기반 역할 식별(근본적인 해결책)
  - 에이전트(C 코드)가 systemd 서비스 목록, 리스닝 포트, 실행 프로세스를 추가 수집해야 한다. 이는 에이전트 스키마 계약 변경 → consumer 파싱 로직 → DB 스키마 확장 → UI 반영까지 전 레이어에 걸친 작업이다. 현재 에이전트와의 스키마 계약 수정이 선행되어야 하므로 별도 작업으로 분리한다.

### 현재 한계
hostname 네이밍 관례(`db-server-01`, `web-server-01`)에 의존하는 수밖에 없다.

## 2. 웹 UI 개선

### 조치 완료
- 인쇄(Print) 기능 추가: `detail`, `list`, `storage`, `network` 4개 페이지
  - `@media print` CSS 적용 — 네비게이션·버튼 숨김, 카드 shadow 제거
  - 인쇄 버튼(`window.print()`) 각 페이지에 추가
  - 인쇄 시 보고서 헤더(페이지 제목, 출력일) 자동 표시
  - 파일시스템 섹션 `page-break-before: always` 적용
- 헤더 브랜드(`ZConverter Assessment`) → `/servers/` 링크로 변경, 별도 "서버 목록" nav 제거
- SSE 자동갱신 상태 + 수집기준시간 한 줄 표시 (`network`, `memory`, `cpu` 상세 페이지)
  - 두 요소를 단일 `display:flex; white-space:nowrap` 컨테이너 안에 배치
- `network.html`에 `fmtKst` 함수 누락 수정 (수집기준시간 표시 무음 실패 버그)
- 서버 상세(`detail.html`) 버퍼 범례 색상 → `#ef4444` (빨간색, 구분 가시성)
- CPU 상세(`cpu.html`)에 `cpu_model` / `cpu_cores` 정적 정보 표시 추가
- CPU 사용률 추이 — agg 토글(평균/최대/p95)과 기간 토글을 시각적 구분선으로 분리

## 3. 시계열 그래프 개선

**목표**: 피크값 표시 등 사용자에게 유의미한 차트 정보 제공.

### 조치 완료
- **avg+max 음영 패턴**: `memory`, `network`, `storage` 상세 차트에 avg(실선) + max(ghost) 쌍 데이터셋 구성. 음영 영역이 집계 구간 내 순간 피크와 평균의 차이를 시각화. 별도 어노테이션 마커 없이도 피크 표현으로 충분하다고 판단.
- **피크탐지 로직 설명**: CPU 상세 페이지에 평균/최대/p95 각각의 용도를 `<ul>` 목록으로 표시.
- **시간 범위 preset 토글**: 상세 페이지(`network`, `cpu`, `storage`, `memory`)에 15분/1시간/6시간/24시간/7일 토글 버튼 구현. 모니터링 니즈 대부분 커버.
- **포인트(노드) 크기**: 전 차트 `pointRadius: 1` 통일 — 존재감은 있으나 시선을 끌지 않는 수준.
- **스왑 Y축**: `beginAtZero: true, suggestedMax: 25` — 고정 0-100% 대신 추이 가시성 우선.
- **네트워크 I/O Y축**: 단위 자동 선택 포매터(`fmtKbChart`) + `NET_Y_SUGGESTED_MAX = 2048` (≈2 kB/s) 기준선.
- **IOPS Y축**: `precision: 0` — 정수 눈금 보장.
- **CPU comp 차트 Y축**: `beginAtZero: true` (기존 `min:0, max:100` 제거 → 자동 스케일로 개별 컴포넌트 추이 가시성 확보).

### 추후 과제
- **시간 범위 직접 입력**: 임의 시작·종료 시각을 사용자가 직접 지정하는 date picker UI. 현재 preset 5단계(15분~7일)로 대부분의 니즈 커버 가능하므로 복잡도 대비 우선순위 낮음. (`chart.html` 포함 모든 페이지에 preset 토글은 구현 완료.)
