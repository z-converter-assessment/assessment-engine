Right-sizing 분류 임계값 참고자료

분류 기준

환경·서버 보고서·AI 진단의 Right-sizing 분류는 recommendation 모듈 단일 진실로 결정. 아래 표의 임계값을 USE Method (Brendan Gregg) Utilization·Saturation 두 축으로 적용해 6 분류 (under_provisioned / over_provisioned / idle / shutdown / optimal / insufficient_data) 산출. 임계 출처는 AWS Compute Optimizer · Azure Advisor · GCP Recommender · Kleinrock 등 산업 표준 종합.

판정 순서

여러 trigger 가 동시 hit 되어도 위에서부터 첫 매칭에서 분류 확정 (short-circuit). 즉 swap 발생 시 cpu/mem 사용률과 무관하게 즉시 under_provisioned, disk capacity 또는 iowait 임계 초과도 cpu 사용률 검사 전 under 확정.

순위 분류 조건
1insufficient_datacpu_p95 또는 mem_p95 null (표본 부재)
2idlecpu_peak <= 1% AND net <= 1 KB/s
3shutdowncpu_p95 <= 3% AND net <= 2 Mbps
4under_provisionedswap_used = true (메모리 saturation short-circuit)
5under_provisionedworst mount used_pct >= 85% (디스크 capacity)
6under_provisionediowait_p95 >= 20% (디스크 IO saturation)
7under_provisionedload_15m / cpu_cores >= 1.0 (CPU saturation — run queue)
8over_provisionedcpu_p95 <= 30% AND mem_p95 <= 50%
9under_provisionedcpu_p95 >= 70% OR mem_p95 >= 80%
10optimal위 모두 미해당

고객 양식 권고

환경 보고서 "조치 필요 호스트"(under/over/idle/shutdown)와 서버 단일 보고서의 "권고" 표시는 mapper _build_recommendation_action 단일 진실. under_provisioned 는 hit 된 trigger 를 증설 권고로 결합 ("/" 구분, 위 임계 카탈로그 trigger 기준), 그 외는 분류별 고정 문구. optimal/insufficient_data 는 조치 불필요라 환경 "조치 필요 호스트"엔 미노출, 서버 단일 보고서엔 상태로 표시. 엔지니어 "판단"(원인 진단)과 별도 축으로, 권고는 다음 행동(조치)을 제시한다.

판단 컬럼 해석

엔지니어 양식 "판단" 컬럼은 위 보조 지표를 아래 우선순위로 평가해 가장 시급한 신호 1개를 자동 진단 — 분류 판정 순서와 동일하게 위에서부터 첫 매칭에서 확정 (short-circuit). 분류(sizing 방향)와 별도 축으로, 입력 지표는 겹치나 출력은 원인 해석 문구다.

순위 조건 판단 문구
1swap_used = true메모리 부족 (스왑 발생)
2iowait_p95 >= 20%디스크 I/O 병목
3load_15m / cpu_cores >= 1.0CPU saturation
4mem_p95 >= 80%메모리 압박
5cpu_p95 >= 70%CPU 압박
6cpu 또는 mem 변동성 >= 1.5변동성 큼 (burst)
7cpu_p95 <= 3%거의 미사용
8cpu_p95 <= 30% AND mem_p95 <= 50%여유 있음 (축소 검토)
9위 모두 미해당정상

운영 신호 임계

Right-sizing 분류와 별도의 운영 안정성 신호 — 환경·서버 엔지니어 양식 KPI / 컬럼 / 세부 카드에 노출. 분류 (under/over/optimal) 가 정상이어도 운영 신호가 발화하면 sizing 보다 운영 조치가 선행되어야 함.

신호 정의 임계 근거 / 용도
데이터 수집 끊김 (gap)last_metric_at 부터 경과 분5분 이상 + 24h 안 발생Agent · MQ · DB write 정지 1차 신호 — 메트릭 신뢰도 zero
OS EOLOS distro · version 의 vendor EOL date 매핑 (정적)임박 또는 지남OS vendor 발표 - 보안 패치 중단, 마이그레이션 선행 필요
Agent 불안정 (reboot)윈도우 안 boot_time 변경 횟수3회 이상비정상 재부팅 누적 - sizing 평가 신뢰도 저하

평가 윈도우

평가 윈도우 표준은 recommendation.WINDOW_DAYS = 14일 (AWS Compute Optimizer 표준). 대시보드·환경 보고서·서버 보고서·AI 진단 모두 본 상수 참조. 보고서 라우터에 한해 ?time_range=15m / 1h / 6h / 24h / 7d / 14d / 30d override 허용. 윈도우가 14일 미만이면 p95 표본 신뢰도가 낮아짐 — 단기 윈도우 결과는 spike 확인용으로 한정 권장.
