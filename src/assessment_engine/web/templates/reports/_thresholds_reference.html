보고서 용어·개념 정리

환경·서버 보고서 본문에 등장하는 핵심 키워드·분류 기준의 정의. 임계값·판정 순서 상세는 아래 절 참조.

키워드 정의
자원 적정성 평가관측 부하 대비 할당 자원의 적정성을 자원 적정성 5 상태(자원 부족·과다·유휴·정상·표본 부족)로 판정해 권고. 분류 기준은 아래 "분류 기준" 절.
USE MethodBrendan Gregg 의 자원 진단 프레임 — Utilization(이용률)·Saturation(포화)·Errors 세 축. 본 보고서는 Utilization·Saturation 두 축 적용.
평균 (avg)윈도우 안 모든 시점값의 산술 평균. 정상 부하의 중심 경향.
p95작은 값부터 정렬해 95% 위치의 값 — 상위 5%(일시 spike)만 초과. 분류 1차 입력. 평균보다 클 수 있음(분포 우측 꼬리).
peak윈도우 안 시점별 최댓값. 실제 관측 burst 강도.
변동성peak / p95 비율 — 클수록 burst 부하. 임계·용도는 "엔지니어 보조 지표" 절.
Saturation (포화)자원이 처리 한계를 넘어 대기열이 쌓이는 신호 — CPU run queue(Linux procs_running · Windows Processor Queue Length)·메모리 페이징(Linux swap page-out · Windows Pages Input/sec 하드폴트)·디스크 IO(Linux await · Windows Avg Disk Queue Length). 발생 시 이용률이 낮아도 증설 신호.
서비스 분류호스트 구동 워크로드를 카테고리(web·db·cache·container 등)로 분류 — 서비스 이름·실행 파일·listen 포트 신호 종합. container 등 런타임 스택은 호스트당 1로 카운트.
메모리 구성전체 메모리 대비 used(사용)·available(가용)·cached(페이지 캐시)·buffers(버퍼) 윈도우 평균 비율. cached/buffers 는 회수 가능 영역이라 available 에 포함.
CPU 분류CPU 시간을 user(응용)·system(커널)·iowait(디스크 대기) 로 분해한 윈도우 평균 비율. iowait 높으면 디스크 병목.
OS EOLOS 배포판·버전의 vendor 지원 종료일(endoflife.date 기준). 임박·경과 시 보안 패치 중단 — 마이그레이션 선행 필요.
운영 신호자원 적정성 평가와 별도의 안정성 신호 — 데이터 수집 끊김(gap)·OS 지원 종료·에이전트 재시작·재부팅 빈도. 분류 정상이어도 발화 시 운영 조치 선행.
신뢰도분류 결과의 확신 수준 단서 — 미관측 축·표본 부족 시 노출. 분류 자체는 가진 데이터로 완결. 상세는 "신뢰도 단서" 절.
평가 윈도우통계 산출 기간 — 보고서 표준 14일. 상세는 "평가 윈도우" 절.

분류 기준

환경·서버 보고서의 자원 적정성 평가는 recommendation 모듈 단일 진실로 결정. 아래 표의 임계값을 USE Method (Brendan Gregg) Utilization·Saturation 두 축으로 적용해 5 상태 (자원 부족 under_provisioned / 과다 할당 over_provisioned / 유휴 idle / 정상 optimal / 표본 부족 insufficient_data) 산출. 조치(증설·축소·종료·통합)는 상태에서 파생. 임계 출처는 AWS Compute Optimizer · Azure Advisor · GCP Recommender · Kleinrock 등 산업 표준 종합.

화면 badge·게이지 색 임계(위험 90% / 주의 75%)는 표시 전용 도메인으로 본 분류 임계와 별개 — 색은 현재 표시값 강조, 분류는 윈도우 통계 기반 적정성 판정. 예: 마운트 87% 는 표시 "주의" 색이면서 동시에 분류 disk >= 85% trigger hit — 모순이 아니라 도메인 차이.

판정 순서

evidence 기반: 자원(CPU/Mem/Disk)별로 가진 축을 신호로 모은다. 자원 부족 (under_provisioned) 은 위험 신호 중 하나라도 hit 되면 발화하고(OR — 누락 0), hit 된 신호를 근거(triggers)로 권고에 노출한다. 과다 할당 (over_provisioned) 은 cpu·mem 이 둘 다 다운사이즈 임계 이하일 때만(AND — 보수적). 포화 축을 못 본 서버를 과다 할당으로 단정하지 않는다.

OS 분기 (Windows): 세 포화 축이 OS별로 다른 실측 신호로 정규화된다 (동일 분류 체계·임계 도메인, 신호원만 상이). CPU 포화는 Linux 실행 큐(procs_running/cores)·Windows Processor Queue Length(run queue/cores >= 2). 메모리 포화는 Linux swap page-out(여유 RAM 에도 상시 baseline 인 Windows pagefile 사용량은 신호 아님)·Windows Memory\Pages Input/sec rate(>= 1000, 하드 페이지 폴트율). 디스크 I/O 포화는 Linux await_p95(Windows 는 await 미발행이라 disk queue 로 대체)·Windows Avg Disk Queue Length(디스크당 큐 >= 2). 각 축은 해당 perflib 를 못 읽거나 미부착(예: OpenStack virtio 에 diskperf 미부착 -> disk queue 빈 배열)이면 그 축만 미관측으로 기록된다("포화 수치 미관측" confidence 단서). 분류는 utilization·capacity·측정된 포화 축으로 완결되며 "표본 부족"이 아니다 — cpu_p95·mem_p95 가 산출되기 때문.

신뢰도 단서

분류는 가진 데이터로 완결하고, 확신을 떨어뜨리는 요인은 별도 단서로만 노출 — 보고서 "신뢰도" 칼럼·환경 자원 평가 "자원 부족" 카드 공통. 비어 있으면 신뢰도 저하 요인 없음.

단서 조건 의미
포화 수치 미관측포화 축 값이 미관측 — 예: Windows 에서 perflib/diskperf 미부착으로 Processor Queue Length·Pages Input/sec·disk queue 중 일부 미발행 (이용률·capacity·측정된 나머지 축은 정상)이용률·capacity·측정된 포화 축으로 분류 완결 — "표본 부족" 아님. 해당 카운터 수집 재개 시 자동 해제.
표본 부족윈도우 기대 표본 대비 실측 비율 50% 미만이용률·포화 p95 전 축 통계 신뢰도 저하 — 짧은 관측·수집 공백 가능성.

권고 (분류 -> 조치)

권고는 분류의 함수 — 환경 보고서 "조치 필요 호스트"(customer)·"자원 부족"(engineer)·서버 단일 보고서 "자원 적정성 평가"가 동일 문구 공유. 자원 부족 (under_provisioned) 은 hit 신호(triggers)별 증설 권고를 "/" 로 결합(임계 재계산 없이 분류 산출 재사용), 그 외는 분류별 고정 문구. 정상 (optimal)·표본 부족 (insufficient_data) 은 조치 불필요라 customer "조치 필요 호스트"엔 미노출. 판독 프레임: 분류(결론) - 진단(원인) - 권고(조치) - 신뢰도(단서).

엔지니어 보조 지표

분류 자체는 위 표의 임계로 결정되지만, 엔지니어 검토 시 원인 진단·증설/축소 방향을 잡으려면 보조 지표가 필요. 아래는 엔지니어 양식에 쓰이는 보조 메트릭의 정의·임계·근거. 통계 개념(평균·p95·peak)은 "보고서 용어·개념 정리" 절. saturation 3축(cpu 포화·메모리 포화·디스크 I/O)은 환경·선택 요약의 "자원 부족" 표에 os-aware 포화 열(CPU 포화·메모리 포화·디스크 I/O)로 노출되고 진단·권고의 근거가 된다 — Linux 는 run queue/swap/await, Windows 는 run queue/paging/disk queue 값이 그 열에 담긴다. 단일 세부 보고서의 CPU/메모리 상세 표는 Linux 축(Load 15m·iowait·swap·Cached·Buffers) 중심이라 Windows 에선 그 셀들이 N/A 이며, Windows 의 포화 근거는 자원 부족 표의 포화 열·진단·권고로 확인한다.

진단 칼럼 해석

"진단" 칼럼(효율화 검토 대상·자원 적정성 평가)은 위 보조 지표를 아래 우선순위로 평가해 가장 시급한 신호 1개를 자동 해석 — 위에서부터 첫 매칭에서 확정 (short-circuit). 분류(적정성 결론)와 별도 축으로, 입력 지표는 겹치나 출력은 원인 해석 문구다.

2disk I/O 포화 (Linux await > 20ms · Windows disk queue >= 2)디스크 I/O 병목

예외 2개 — 표본 부족(insufficient_data) 분류 호스트는 신호 대신 원인을 진단 (오프라인 — 에이전트 미가동 / 누락 메트릭 명시 / 윈도우 내 표본 부족). 오프라인 호스트는 진단 앞에 "오프라인" 접두 — 분류는 윈도우 측정 기반 그대로 유지.

운영 신호 임계

자원 적정성 평가와 별도의 운영 안정성 신호 — 분류가 정상이어도 발화하면 적정성 판정보다 운영 조치가 선행되어야 함. 실시간 현황 페이지 운영 신호 카드에 3종 노출. 보고서는 발행 윈도우 기준이라 전역 신호(gap·에이전트 불안정)는 미표시 — OS EOL 만 표시하고, 재부팅·에이전트 재시작은 윈도우 안 카운트로 세부 서버 목록 시스템 안정성 칼럼에 표시.

평가 윈도우

자원 적정성 평가 표준은 recommendation.WINDOW_DAYS = 14일 — 보고서·서버 목록 분류 기준. 보고서 발행 시 15m / 1h / 6h / 24h / 7d / 14d / 30d 구간 선택 가능하며 분류·통계·세부 목록 모두 선택 구간으로 평가. 모니터링 현황 카드 — 환경 개요(평균 활용률)는 최근 24시간 고정(DASHBOARD_TIME_RANGE), 환경 자원 평가는 24시간 기본(구간 선택 가능) — 표준 평가(14일)와 의도 분리(최근 현황 모니터링). 버킷(집계 단위)은 구간별 자동 결정. 윈도우가 너무 짧으면 p95 표본 신뢰도가 낮아짐 — 단기 구간 결과는 spike 확인용으로 한정 권장.
